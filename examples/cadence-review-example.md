# Cadence Review Example

> Example instance material for DAOS.
> This file demonstrates what a lightweight cadence review can look like in practice.
> It is not canonical framework doctrine.

## 1. Heartbeat / quick check-in

- What is foreground right now? Operations and client work
- What feels most at risk of slipping? waiting-on follow-ups and one important build task that keeps losing focus to inbox churn
- Is anything newly urgent, blocked, or noisy? one promised response date passed; low-value reminder noise is starting to accumulate
- What is the smallest useful next move today? refresh the waiting-on list and lock the top 3 priorities before doing anything else

## 2. Weekly review

- What moved this week? client drafting moved, two operational follow-ups closed, one build task finally got scoped
- What stalled this week? research lane stayed stagnant because it never regained foreground time
- Which lane carried the most pressure? operations
- Which reminders were useful versus noisy? deadline-linked reminders helped; broad “check in on everything” nudges did not
- What should be promoted, paused, or dropped? promote the build task into the active focus set, pause speculative research cleanup, drop one redundant reminder stream

## 3. Monthly reset

- Which lanes are still real and active? personal, operations, client work, build / projects
- What should change in the current lane map? research should stay present but move explicitly to low-foreground stalled status until reactivated
- What has become clutter? old follow-up tasks that were effectively resolved but never closed cleanly
- What deserves a stronger support system? client waiting-on tracking and weekly build review protection
- What should be simplified? reduce duplicate reminder surfaces and keep one clear review layer

## 4. Event-trigger review

- What changed? a client lane that was merely active became dependency-heavy and higher pressure
- What layer should absorb the change? the lane snapshot plus reminder/follow-up defaults
- Does a default need to be updated? yes — stronger waiting-on visibility for external dependencies
- Does something need to be reclassified? yes — one build task moves from background to foreground, one research lane stays stalled rather than pretending to be active

## 5. Keep / add / remove

- Keep: concise top-3 focus set, explicit ask-vs-act boundary, weekly lane pressure check
- Add: lane-specific snapshot for client work and one cleaner waiting-on dashboard
- Remove: low-value broad reminder pings that do not lead to decisions

## 6. Why this helps

A cadence review like this helps because it:
- recenters the true foreground
- catches drift before it compounds
- shows which support behaviors are helping versus adding noise
- creates a clean bridge from setup into ongoing calibration
