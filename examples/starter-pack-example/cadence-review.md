# Cadence Review

> Filled starter-pack example.
> Mirrors `starter-pack/cadence-review.md` after the first operating baseline already exists.

## 1. Heartbeat / quick check-in

- What is foreground right now? operations and client work
- What feels most at risk of slipping? waiting-on follow-ups and one protected build task
- Is anything newly urgent, blocked, or noisy? one promised reply is overdue; reminder noise is starting to widen
- What is the smallest useful next move today? refresh the waiting-on list and lock the top 3 priorities before new inbox work

## 2. Weekly review

- What moved this week? two operational follow-ups closed and one build task finally got scoped
- What stalled this week? research never regained enough foreground to move
- Which lane carried the most pressure? operations
- Which reminders were useful versus noisy? deadline-linked reminders helped; broad generic nudges did not
- What should be promoted, paused, or dropped? promote one build task into the active focus set; pause speculative cleanup; drop one redundant reminder stream

## 3. Monthly reset

- Which lanes are still real and active? personal, operations, client work, build / projects
- What should change in the current lane map? keep research visible but explicitly stalled instead of pretending it is active
- What has become clutter? resolved follow-up items that were never closed cleanly
- What deserves a stronger support system? client waiting-on tracking and weekly build review protection
- What should be simplified? duplicate reminder surfaces

## 4. Keep / add / remove

- Keep: concise top-3 focus set, explicit approval boundary, weekly lane pressure check
- Add: one cleaner waiting-on dashboard and stronger lane-specific client follow-up support
- Remove: low-value broad reminder pings with no attached decision
