# Starter Pack Example

> Example instance material for DAOS.
> This folder demonstrates what a filled starter-pack can look like as a whole.
> It is not canonical framework doctrine.

## What this folder is for

Use this if you want to see the copyable `starter-pack/` in a filled state.

This example now includes the same locked baseline doctrine files as the starter pack, alongside filled operator-owned files.

That includes the public reset/wake-up artifact:
- `wiki/cache/reset-handoff.md`

This is useful when:
- you want to understand the target shape before filling your own pack
- you want a folder-level example instead of jumping between separate example files
- you want to see how the starter-pack artifacts relate to each other as one instance

## File order

1. `assistant-charter.md`
2. `operating-profile.md`
3. `lane-snapshot.md` *(optional, only for a high-friction lane)*
4. `cadence-review.md` *(later-use review layer, not first install output)*

## How to use this example

- read it for shape, not for exact answers
- copy the pattern, not the specifics
- keep your own first pack leaner than you think

## What this should make clearer

A good starter pack should feel like:
- one lightweight operating baseline
- one coherent folder
- no giant intake burden
- clear room for later calibration
