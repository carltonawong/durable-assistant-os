# Lane Snapshot Example

> Example instance material for DAOS.
> This file demonstrates what a filled lane snapshot can look like.
> It is not canonical framework doctrine.

## 1. Lane identity

- Lane name: Client work
- Why this lane exists: this lane holds active external delivery obligations that need reliable visibility and follow-through
- Current owner / operator if relevant: user is primary owner; assistant supports tracking, drafting, and follow-up

## 2. Current state

- Status: pending
- Foreground: yes
- Pressure: high
- Short note: two client responses are outstanding, and forward motion depends more on clean waiting-on visibility than on generating new internal tasks

## 3. What matters now

- Main outcome in this lane right now: keep deliverables moving without missing a response or next-step handoff
- Main risk of drift or failure: buried waiting-on items create fake calm until deadlines compress suddenly
- Current blocker or dependency: external responses from two stakeholders
- Smallest useful next move: produce a clean waiting-on list and pre-draft the next follow-up messages

## 4. Support posture

- What kind of help is most useful in this lane: explicit waiting-on tracking, concise follow-up drafts, and deadline visibility
- What kind of help is usually noise in this lane: brainstorming unrelated improvements before the dependency clears
- Default reminder / follow-up posture: gentle same-day resurfacing for overdue replies, stronger prompt once a promised date slips
- Approval or caution boundary specific to this lane: assistant may draft follow-ups, but external sends and commitments require approval

## 5. Memory / continuity notes

- What should stay easy to recover: who is waiting on what, promised dates, and the current next outbound action
- What belongs in durable notes instead of this snapshot: detailed project history, full meeting notes, and contract specifics
- What should stay out of the hot path unless reactivated: old completed client threads and resolved negotiation context

## 6. Review triggers

Refresh this lane snapshot when:
- a stakeholder replies or goes silent past expectation
- the lane shifts from pending to active or stalled
- pressure materially changes
- a deliverable deadline moves
- the current follow-up posture stops helping

## 7. Why this is useful

This kind of snapshot helps because it gives the assistant one compact lane-specific operating picture:
- current state
- current dependency
- useful support mode
- next move

That is enough to improve continuity without turning the lane into a bureaucracy.
