# DAOS v0.2.8 - Runtime obedience and returning-workstream hardening

DAOS v0.2.8 packages the public hardening that landed after v0.2.7 into a small patch checkpoint.

## Added

- `use-daos init --use-detected-home` gives operators an explicit opt-in path to install the starter pack into a detected assistant operating home instead of silently creating a disconnected `~/.daos`.

## Changed

- README and public docs now sharpen the DAOS boundary as a portable context-continuity layer, including context-recovery and returning-workstream preflight language.
- Runtime-integration guidance now defines a deterministic compaction fallback invariant: if a higher-level LLM summary fails, the runtime should still preserve bounded, redacted handoff context before discarding a window.
- npm/package smoke tests now select the platform-native npm command so WSL/Linux gates do not fail on Windows shim paths.
- Package metadata and generated manifests now advertise `0.2.8` / `v0.2.8`.

## Hardened

- Adapter preflight coverage now blocks sensitive actions when the only supporting signal is remembered memory evidence; memory remains context, not permission.
- Freshness-sensitive claims such as release, publish, branch/tag, runtime-health, scan, and test-result status remain tied to live authority instead of stale memory.

## Verification

Before release, rerun the full Python suite, npm wrapper/package/release-front-door gates, npm pack dry-run, and a packed-tarball install smoke from a fresh consumer project.

## Scope

Patch checkpoint only: no hosted runtime, autonomous control layer, private integration, or new memory layer.
