# DAOS v0.1.5

Release date: 2026-04-24

## Intended scope

`v0.1.5` is a starter-pack trust and script-safety hardening release on top of `v0.1.4`.

It keeps DAOS starter-pack-first: users can still copy and use the pack manually, while optional scripts are clearer about what they do and whether they modify files.

## Changes

### Added
- `scripts/daos_memory_parity.py`, a stdlib-only read-only auditor for checking whether a DAOS pack's memory surfaces match DAOS parity rules.
- `scripts/daos_core/parity.py`, the reusable parity-audit implementation.
- `docs/memory-parity-auditor.md`, documenting the parity auditor's purpose, checks, output shape, and safety posture.
- `docs/script-safety.md`, documenting the starter-pack-first trust model and current script safety commitments, including no intentional credential-location reads.
- Tests for memory parity checks and script-safety regressions.

### Changed
- README and quickstart now present read-only checks and manual checklist alternatives before optional helper scripts.
- `daos_validate.py` and `daos_memory_parity.py` help text now explicitly says the checks are read-only and modify no files.
- Generated and updater-created manifests now use `framework_version: v0.1.5`.

### Hardened
- `daos_update.py` and `daos_portability.py` remain in-repo, but are no longer README/quickstart first-run commands.
- Advanced write-capable maintenance/portability tools are documented as opt-in tools rather than front-door setup requirements.
- Regression coverage now guards against accidental network/subprocess imports in scripts.
- Regression coverage now guards against advanced write-capable script names returning to front-door README/quickstart command lists.

## Explicit non-goals

- no new memory layer
- no auto-repair mode
- no cron scheduler or runtime integration change
- no automatic modification by the parity auditor
- no deletion of existing advanced scripts just because they are write-capable
- no broad architecture expansion beyond the trust/safety hardening slice
