# DAOS v0.2.5 Release Notes

**Release type:** patch / public enforcement hardening  
**Date:** 2026-05-14

`v0.2.5` packages the first public enforcement layer for DAOS after the `v0.2.4` doctor-adapter patch. It does not add a new runtime or memory layer. It makes the public repo harder to drift by adding CI gates and a concise maintenance protocol.

## Added

- Added a read-only GitHub Actions workflow for pull requests and pushes to `main`.
- The workflow runs:
  - full Python unit tests
  - npm wrapper tests
  - package payload checks
  - packed-install smoke tests
  - release/front-door consistency checks
  - `npm pack --dry-run --json`
- Added regression tests that keep the workflow read-only and prevent accidental npm publish, GitHub Release creation, or write-permission requests.
- Added `docs/maintenance.md`, a manual-first DAOS upkeep protocol with optional automation guardrails.

## Changed

- Bumped package metadata and generated framework manifests to `0.2.5` / `v0.2.5`.
- Included `docs/maintenance.md` and this release note in the npm package payload.
- Adjusted the package-size regression budget intentionally for the new packaged maintenance doc while keeping the payload small.

## Why this matters

Before this patch, public DAOS had the architecture and local tests, but GitHub did not enforce the same proof loop on PRs. `v0.2.5` moves more of the private operating discipline into portable public form:

- CI catches broken tests and package drift before merge.
- The maintenance protocol tells operators how to keep hot cache, reset handoff, durable promotion, and runtime proof honest.
- Automation remains optional and read-only-first instead of becoming hidden runtime behavior.

## Migration notes

No user migration is required from `v0.2.4` to `v0.2.5`.

Existing DAOS homes do not need file rewrites. To use the new maintenance guidance, read:

```text
docs/maintenance.md
```

## Boundaries

This release does not claim live runtime obedience by itself. GitHub CI proves repository/package checks; runtime obedience still requires `use-daos doctor` evidence from the target assistant runtime.

No npm/GitHub publishing is implied by this file until the `v0.2.5` tag/release/publish steps are explicitly run.
