# DAOS v0.2.0 Release Notes

Date: 2026-04-29

## Summary

`v0.2.0` turns DAOS from a mostly manual starter pack into a small installable continuity harness.

The new first-user loop is:

```bash
npx use-daos init
npx use-daos setup
npx use-daos check
npx use-daos on
npx use-daos reset-test
```

`use-daos init` installs the mandatory DAOS baseline, scans for existing agent instruction files, and stages or applies coexistence guidance safely. `use-daos setup` activates the minimum assistant charter, operating profile, current focus, and reset handoff. `use-daos check`, `use-daos on`, and `use-daos reset-test` then prove the pack is readable, visible, and recoverable. No-args `use-daos` still shows a compact `DAOS Status` report with a `DAOS On` section that summarizes what the active continuity surfaces currently contain.

## Why this matters

DAOS is not trying to become a full assistant runtime. It is the reliability layer beside a runtime.

This release makes that reliability layer easier to verify:
- easier first install
- guided minimum setup
- visible status after install
- safer coexistence with existing agent systems
- reset recovery proof before declaring the setup complete
- package-level smoke proof
- tested behavior instead of doctrine-only instructions

## New first-user surface

```bash
npx use-daos init
npx use-daos setup
npx use-daos check
npx use-daos on
npx use-daos reset-test
```

`use-daos init`:
- installs the starter-pack wiki/cache baseline
- scans nearby instruction carriers such as `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.cursorrules`, Cursor rules, Copilot instructions, Hermes instructions, and OpenClaw/Quinn instructions
- asks before editing existing instruction files in interactive mode
- writes `.daos/import-stage/instruction-scan.md` when review is needed
- backs up approved instruction edits under `.daos/backups/instructions/`

`use-daos setup`:
- asks eight short personalization questions
- writes the minimum assistant charter, operating profile, hot cache/current focus, and reset handoff
- refuses non-interactive silent defaulting unless all answers are supplied or `--accept-defaults` is explicitly used

`use-daos check`, `use-daos on`, and `use-daos reset-test`:
- default to the active DAOS home (`DAOS_HOME` or `~/.daos`) when no pack path is provided
- check the activated pack, show the active continuity surfaces, and verify reset recovery
- end the first-run sequence with `You're complete!` when reset recovery passes

No-args `use-daos`:
- defaults to status
- shows setup health
- shows `DAOS On`
- summarizes Hot Cache, Hot Cache Log, Reset Handoff, and Agent Continuity
- surfaces setup, continuity, and bridge-review actions separately

`use-daos on` is also available as a direct alias for the current DAOS On/status surface, including explicit existing-home paths such as:

```bash
use-daos on /path/to/existing-assistant-home
```

A DAOS home is the folder with the DAOS pack/wiki surfaces. The default new-user home is `~/.daos`, but existing assistant homes such as an OpenClaw-style `.openclaw` folder can be used directly when they already contain the DAOS `wiki/cache/` surfaces.

## Safety posture

This release keeps the core DAOS trust boundary:

- no silent instruction edits
- no arbitrary old memory import by default
- approved edits create backups
- non-interactive mode stages review instead of applying edits
- current verified reality still outranks all memory
- active project checkpoints that change future assumptions should be captured durably, not left only in chat, hot cache, or short transition logs

Existing private/agent-specific memory can continue to orient its own agent. DAOS becomes the shared continuity layer across agents and tools.

## Packaging

This release adds a thin npm wrapper over the Python reference CLI.

The wrapper:
- locates the bundled Python entrypoint relative to the package root
- discovers Python via `DAOS_PYTHON`, `python3`, `python`, then `py -3`
- forwards stdout, stderr, cwd, env, and exit codes
- preserves interactive TTY prompts
- prints a clean Python-missing message

Package payload is allowlisted so npm packages exclude tests, large docs assets, and Python bytecode caches.

## Scope

This is a product-surface release, not a hosted app, daemon, scheduler, or autonomous assistant runtime.

The point of `v0.2.0` is to make DAOS immediately installable, activatable, visible, and safer to introduce into an existing agent workspace.
