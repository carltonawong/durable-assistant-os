# DAOS v0.2.4 Release Notes

Date: 2026-05-13

## Summary

`v0.2.4` is a doctor-adapter patch. It keeps the `use-daos doctor` proof ladder from `v0.2.3`, then adds a conservative read-only Hermes runtime detector so supported adapters can produce runtime evidence without hand-writing a JSON fixture first.

The important change is not broader automation. It is a smaller proof surface: DAOS can now inspect visible Hermes wiring and report it in the same evidence shape that `doctor` already understands.

## Changes

- Added `collect_runtime_evidence(pack_dir, runtime=None, detect=False)` for read-only runtime evidence collection.
- Added `use-daos doctor <pack> --runtime hermes --detect-runtime` as the first built-in runtime detector path.
- Allowed `--runtime <path-to-json>` to behave like a runtime evidence fixture while preserving `--runtime-file` as the explicit compatibility path.
- Documented the Hermes detector in README and quickstart.
- Bumped package metadata and generated framework manifests to `0.2.4` / `v0.2.4`.

## Hardened

- The Hermes detector returns the existing doctor evidence shape: `runtime`, `startup_root`, `daos_home`, `prompt_precedence`, `reset_wake`, and `unexpected_writes`.
- The detector intentionally reports `reset_wake.one_shot_proven: false` unless a real reset/session proof is provided.
- Runtime detection stays read-only: it checks visible file/env wiring and does not modify DAOS homes, restart services, or auto-fix runtime state.

## Why This Matters

A DAOS install can have the right files and still be unproven at runtime. `v0.2.3` made that distinction visible through fixture evidence. `v0.2.4` makes the first adapter path easier to inspect:

```bash
use-daos doctor /path/to/existing-assistant-home --runtime hermes --detect-runtime
```

That command can prove detected wiring, while still refusing to claim full one-shot reset recovery without observing the actual reset behavior.

## Upgrade Notes

No user migration is required from `v0.2.3` to `v0.2.4`.

Existing DAOS homes are not rewritten automatically. New package installs receive the updated CLI/docs. Existing users can keep using `--runtime-file`; Hermes users can also try the read-only detector path above.

## Known Non-Goals

- No automatic runtime repair.
- No service restart behavior.
- No claim that one-shot reset recovery is proven without actual session proof.
- No automatic rewrite of existing user-owned DAOS homes.
- No npm/GitHub publishing is implied by this file until the `v0.2.4` tag/release/publish steps are explicitly run.
