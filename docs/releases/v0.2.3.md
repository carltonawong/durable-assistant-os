# DAOS v0.2.3 Release Notes

Date: 2026-05-10

## Summary

`v0.2.3` is a release-prep hardening patch for the v0.2 line. It adds a read-only doctor/proof ladder, improves public package metadata, fixes a first-run instruction-scan path mismatch, and makes freshness-sensitive claims more explicit in the public continuity model.

## Changes

- Added `use-daos doctor`, a read-only receipt that distinguishes installed, bridged, activated, and proven DAOS states.
- Added `use-daos boot-check` runtime hierarchy checks for startup root, prompt/context precedence, session topology, reset/handoff wiring, and cache freshness.
- Added `docs/reset-current-state-receipt.md`, a small proof shape for reset recovery that preserves objective, last verified result, approval boundary, stale risk, and the first live fact to recheck.
- Fixed the instruction bridge review path so scan reports land at `import-stage/instruction-scan.md` inside the DAOS home rather than under a nested `.daos/import-stage/` path.
- Added npm/GitHub package metadata keywords, repository, homepage, and issue links.
- Updated the public framing from memory-first language toward continuity: DAOS keeps the right context visible across resets, gaps, tool changes, and live verification.
- Bumped package metadata to `0.2.3` and generated framework manifests to `v0.2.3`.

## Why This Matters

This patch makes DAOS easier to trust after install. A new user can run the normal first-run loop, then use the doctor/boot checks to see whether the pack is merely present or actually wired into the runtime in a DAOS-first way. The freshness-sensitive claim language also reduces the risk that stale memory or cached notes are treated as current operational truth.

## Verification

Release verification for this patch:

```bash
python -m unittest discover -s tests -v
npm run test:wrapper
npm run test:package
npm run test:pack-install
npm run test:release-front-door
npm pack --dry-run --json
```

Expected result:

- full Python test suite passes
- npm wrapper, package payload, packed-install smoke, and release-front-door gates pass
- npm dry-run package includes the `v0.2.3` release note and excludes local proof/scratch artifacts
- fresh generated manifests report `framework_version: v0.2.3`

## Upgrade Notes

No user migration is required from `v0.2.2` to `v0.2.3`. Existing DAOS homes are not rewritten automatically. New installs receive the updated package metadata, doctor/boot-check commands, and public docs. Existing users can run `use-daos doctor` or `use-daos boot-check` against their current DAOS home when they want a read-only wiring receipt.

## Known Non-Goals

- No automatic rewrite of existing user-owned DAOS homes.
- No external service, hosted runtime, or credential integration.
- No import of arbitrary old memory files.
- No broad eval-corpus publication.
- No change to the approval boundary for publishing, tagging, or npm release actions.
