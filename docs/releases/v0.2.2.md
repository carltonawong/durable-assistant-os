# DAOS v0.2.2 Release Notes

Date: 2026-05-05

## Summary

`v0.2.2` is a baseline-compression patch. It reduces the default token cost of a DAOS-enabled agent startup by keeping `starter-pack/AGENTS.md` as a short operating contract and moving detailed maintenance/automation doctrine into conditional reference material.

## Changes

- Compressed `starter-pack/AGENTS.md` so startup reads focus on the default read path, hard rules, reset/wake-up rule, and short maintenance loop.
- Moved the fuller maintenance and automation reference into `starter-pack/wiki/cache/MEMORY-OPERATING-MODEL.md`.
- Added the explicit rule that default-read memory surfaces should stay small and that detailed doctrine, schemas, historical material, and maintenance recipes should live behind targeted references.
- Clarified the hot-cache doctrine around compact `Current Focus` entries, fallback-only hot-cache-log reads, and pruning stale temporary context after durable state exists.
- Bumped package metadata to `0.2.2`.

## Why This Matters

DAOS should make continuity cheaper, not make every new agent session reread all doctrine. The installed baseline now preserves the same operating rules while making detailed memory-system guidance conditional and keeping active context bounded.

Expected result:

## Upgrade Notes

No user migration is required from `v0.2.1` to `v0.2.2`.

Existing DAOS homes are not rewritten automatically. New installs receive the compressed baseline. Existing users can manually adopt the same pattern by keeping default-read instruction files short and moving detailed maintenance doctrine into targeted reference pages.

## Known Non-Goals

- No first-run flow changes.
- No product positioning changes.
- No eval corpus reorganization.
- No runtime command behavior changes.
- No hot-cache section-name migration; `Current Focus` remains the compatibility section and now carries compact active-context entries.
- No automatic rewrite of existing user-owned DAOS homes.
