# DAOS v0.1.3

Release date: 2026-04-22

## Intended scope

`v0.1.3` is a patch hardening release.

It does not change the DAOS pack schema or create a new runtime layer.
It makes the durable wiki/docs side of DAOS more explicit and more governable.

## Changes

### Added
- `docs/wiki-governance.md` as the canonical DAOS page for durable wiki page metadata and governance.

### Changed
- README now points to the wiki-governance doctrine and advances the documented baseline to `v0.1.3`.
- `docs/memory.md` and `docs/public-memory-page.md` now say more clearly that durable wiki/docs memory needs lightweight page governance, not just a memory stack.
- `docs/pack-schema.md` now clarifies that `LaneSnapshot.status` is lane operating state, not wiki-page lifecycle status.
- `starter-pack/wiki/WIKI.md` and the filled starter-pack example now teach the compact durable-page discipline directly inside the installed baseline.

### Hardened
- DAOS now explicitly separates page `Status` from subject `State`.
- DAOS now explicitly says schema-only migration should preserve historical `Last Updated` instead of flattening freshness history.
- DAOS now more clearly distinguishes durable page structure from drift-prone operational verification via `Source of Truth` and `Last Verified`.

## Explicit non-goals

- no pack-schema rename from `LaneSnapshot.status`
- no new DAOS runtime integration layer
- no broad page-type taxonomy mandate across every install
- no migration boundary that would justify a minor or major release

## Release intent

Use this release to make DAOS durable memory more legible in practice:
- durable pages should read as current, legacy, or archived more clearly
- operating condition should not be confused with page lifecycle
- historical freshness should survive cleanup work
- drift-prone pages should say what reality should win when docs drift
