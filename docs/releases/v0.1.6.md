# DAOS v0.1.6

Release date: 2026-04-25

## Intended scope

`v0.1.6` is a public-surface hardening release on top of `v0.1.5`.

It keeps DAOS starter-pack-first while making the public repository easier for a stranger to understand, install, and audit without Carlton's private OpenClaw/Hermes context.

## Changes

### Changed
- Compressed the root README into a tighter front door: who DAOS is for, why it exists, how to start, and what proof already exists.
- Restored the fragile-assistant vs DAOS memory-surfaces visual near the top of the README so the core operating contrast is immediately visible.
- Added the Karpathy LLM Wiki pattern to the front-door/starter-pack context so adopters understand the markdown-wiki foundation rather than treating `wiki/` as arbitrary folders.
- Rewrote the quickstart around the copy/fill/use loop instead of a broad reference tour.
- Reduced example sprawl and kept `examples/starter-pack-example/` focused on filled user-owned files rather than a duplicated locked baseline spine.
- Updated filled-example bootstrap behavior so it starts from `starter-pack/` and overlays the filled example files, preserving the locked baseline.
- Bumped generated/updater manifest framework baseline to `v0.1.6`.

### Hardened
- Removed public `docs/plans/` workbench artifacts from `main`; proof of work remains in releases, changelog, tests, tags, and git history.
- Clarified what `wiki/` means in the starter pack: a plain markdown knowledge base, not Wikipedia, a hosted app, or a special database.
- Added manual-first and optional-automation maintenance guidance to the starter-pack agent rules.
- Reduced duplicate baseline files so future doctrine changes have fewer places to drift.

## Explicit non-goals

- no new memory layer
- no new runtime integration
- no cron scheduler requirement
- no private roadmap publication
- no conversion of optional scripts into the product front door
- no broad architecture expansion beyond public repo clarity and installability
